# View — шаблонизатор cwfr

Модуль рендерит текстовые шаблоны (HTML и любые другие) по данным из
`json_doc_t`. Синтаксический разбор выражений выполняется методом
рекурсивного спуска (`viewexpr.c`), значения типизированы: строки, числа,
булевы, null и JSON-контейнеры. Распарсенные шаблоны кэшируются в
`viewstore` — файл читается и разбирается один раз, дальше рендер идёт по
готовому дереву тегов.

## Быстрый старт

### Из обработчика HTTP

```c
#include "json.h"

void get(httpctx_t* ctx) {
    json_doc_t* doc = json_create_empty();
    json_token_t* root = json_token_alloc(JSON_OBJECT);
    json_set_root(doc, root);
    // ... наполнить документ данными ...

    // storage "views", файл <root>/index.html
    ctx->response->send_view(ctx->response, doc, VIEW_ESCAPE, "views", "/index.html");

    json_free(doc);
}
```

Путь принимает printf-формат: `send_view(..., VIEW_ESCAPE, "views", "/user_%d.html", id)`.
При ошибке разбора шаблона клиенту уйдёт строка `Render view error`.

### Напрямую

```c
#include "view.h"

char* html = render(doc, VIEW_ESCAPE, "views", "/index.html");
if (html != NULL) {
    // ... использовать ...
    free(html); // владение у вызывающего
}
```

`render` возвращает `NULL`, если шаблон не найден, синтаксически неверен или
не настроен `viewstore`. Отсутствующие в документе переменные ошибкой не
считаются — они рендерятся пустой строкой.

### Режим экранирования

Второй аргумент `render` / третий `send_view` — `view_escape_e`:

| Режим | Для чего | Значения `{{ }}` |
|-------|----------|------------------|
| `VIEW_ESCAPE` | HTML-страницы и письма | `& < > " '` → `&amp; &lt; &gt; &quot; &#39;` |
| `VIEW_RAW` | текстовые письма, не-HTML | как есть |

Режим действует на весь рендер, включая `{* include *}`. Экранирование
выполняется при записи значения, после всех модификаторов, поэтому
закэшированное дерево от режима не зависит.

### Настройка storage

Шаблоны читаются из именованного storage (`config.json`, секция `storages`):

```json
"storages": {
    "views": {
        "type": "filesystem",
        "root": "/path/to/app/views"
    }
}
```

Подходит и `s3`-storage — модуль работает через общий интерфейс `storage`.

## Синтаксис шаблонов

Три вида тегов:

| Тег | Назначение |
|-----|------------|
| `{{ выражение }}` | вывод значения |
| `{% ... %}` | условия и циклы |
| `{* include /path *}` | вставка другого шаблона |

Одиночные `{`, `}`, `%`, `*` — обычный текст, экранировать не нужно.

### Вывод значений

```html
<h1>{{ user.name }}</h1>
<p>Цена: {{ price * (1 - discount) }}</p>
<p>Первый тег: {{ user.tags[0] }}, следующий: {{ items[pos + 1].title }}</p>
```

Правила вывода по типу результата:

| Тип | Вывод |
|-----|-------|
| строка | текст; в режиме `VIEW_ESCAPE` — HTML-экранированный; NUL-байт → `�` (U+FFFD) |
| число | целые без дробной части (`42`), дробные — кратчайшая точная форма (`9.99`) |
| bool | `true` / `false` |
| null, отсутствующее значение | пустая строка |
| объект / массив | пустая строка (выводите поля или обходите циклом) |

### Условия

```html
{% if user.age >= 18 && user.role == 'admin' %}
    админ
{% elseif user.age >= 18 %}
    взрослый
{% else %}
    несовершеннолетний
{% endif %}
```

Условие — любое выражение. Истинность значения:

* **истинно**: непустая строка, ненулевое число, `true`, непустой объект/массив;
* **ложно**: `''`, `0`, `false`, `null`, пустой контейнер, отсутствующее значение.

### Циклы

```html
{% for item in items %}
    {{ index + 1 }}. {{ item.title }}
{% endfor %}

{% for value, key in settings %}
    {{ key }} = {{ value }}
{% endfor %}
```

* `{% for элемент in коллекция %}` — обход массива или объекта.
* Второе имя после запятой — ключ: для массива это числовой индекс,
  для объекта — строковый ключ.
* Без явного ключа доступна переменная `index` (число, участвует
  в арифметике).
* Коллекция — любое выражение: `{% for x in data.rows[2] %}`.
* Циклы вкладываются; во вложенном доступны переменные всех внешних циклов.
* Имена элемента и ключа перекрывают одноимённые поля корня документа.

### Вставка шаблонов

```html
{* include /partials/header.html *}
```

Путь — внутри того же storage. Вставка рекурсивная, глубина ограничена 100
(защита от самовключения).

## Выражения

### Литералы

```
42   9.99   -5.5e2   'строка'   "тоже строка"   true   false   null
```

В строках работают `\'`, `\"`, `\\`, `\n`, `\t`, `\r`.

### Переменные

Идентификатор (`[A-Za-z_][A-Za-z0-9_]*`), затем путь из `.поле` и
`[индекс]`. Индекс — любое выражение: числовое для массива, строковое для
объекта (`obj[key]`, `obj['literal']`). Выход за границы массива, обращение
к полю скаляра, отрицательный или дробный индекс дают null, а не ошибку.

### Операторы (по убыванию приоритета)

| Приоритет | Операторы | Замечания |
|-----------|-----------|-----------|
| 1 | `\|` | модификатор, привязывается к ближайшему операнду |
| 2 | `!` `-` (унарные) | `!` — логическое отрицание любого значения, `-` — только числа |
| 3 | `*` `/` `%` | только числа; `/ 0` и `% 0` дают null |
| 4 | `+` `-` | только числа (конкатенации строк нет) |
| 5 | `<` `<=` `>` `>=` | числа — численно, строки — лексикографически; разные типы не упорядочены (false) |
| 6 | `==` `!=` | значения разных типов не равны (`'1' != 1`) |
| 7 | `&&` | короткозамкнутый |
| 8 | `\|\|` | короткозамкнутый |

Скобки `( ... )` группируют как обычно. Одиночные `=` и `&` —
синтаксическая ошибка. Глубина вложенности выражения ограничена 32, число
операндов и модификаторов в одном выражении — 1024.

```html
{% if (a + b) * 2 > limit && !(banned || muted) %} ... {% endif %}
{% if count % 2 == 0 %}чётный{% endif %}
{{ matrix[i][j] * k }}
```

Операции над несовместимыми типами (`'a' + 1`) вычисляются в null — рендер
не падает, значение выводится пустым.

## Модификаторы

`значение | имя` или `значение | имя(аргументы)`; цепочка применяется слева
направо. Модификатор — постфиксный оператор с наивысшим приоритетом:
`{{ a * b | round(2) }}` — это `a * (b | round(2))`, для всего произведения
нужны скобки. Аргументы — любые выражения (до трёх), в том числе с
модификаторами. Работают во всех тегах, включая `{% if %}` и `{% for %}`.

```html
<h1>{{ title | trim | upper }}</h1>
<p>{{ price | number(2, ',', ' ') }}</p>
{% if items | length > 3 %} ... {% endif %}
<script>const data = {{ data | json | raw }};</script>
```

| Модификатор | Аргументы | Результат |
|-------------|-----------|-----------|
| `raw` | — | вывод без экранирования; только в корне `{{ }}`, последним |
| `nl2br` | — | экранирование + переносы → `<br>`; только в корне `{{ }}`, последним; в `VIEW_RAW` — текст как есть |
| `url` | — | всё, кроме `A-Z a-z 0-9 - _ . ~`, → `%XX` (пробел — `%20`) |
| `json` | — | JSON любого значения; `< > & '` U+2028 U+2029 → `\uXXXX`; глубже 32 — null |
| `upper` `lower` | — | регистр, с кириллицей; битый байт UTF-8 → `�` (U+FFFD) |
| `capitalize` | — | первая буква — заглавная, остальное без изменений |
| `trim` | — | пробелы по краям, включая неразрывные |
| `truncate` | `n`, `suffix='…'` | первые `n` символов + суффикс, если обрезано |
| `replace` | `from`, `to` | все вхождения слева направо |
| `default` | `value` | `value`, если null или `''` (`0` и `false` остаются) |
| `abs` | — | модуль числа |
| `round` | `n=0` | округление до `n` (0–15) знаков, половина — от нуля; число |
| `number` | `decimals=0`, `dec_sep='.'`, `thousands_sep=''` | форматированная строка |
| `length` | — | символы строки / элементы контейнера; null → 0 |
| `first` `last` | — | крайний элемент массива, значение объекта или символ строки |
| `join` | `sep=''` | элементы контейнера через разделитель |

После скобок и после модификатора можно продолжить путь: `(users | first).name`,
`users | last.name`, `(obj).list[0]`. У скаляра полей нет — результат null.

Строки несут длину (`viewexpr_value_t.length`) и могут содержать NUL-байты:
модификаторы, сравнения и поиск по ключу работают по длине, `json` пишет
`\u0000`, `url` — `%00`, вывод в шаблон — U+FFFD (`render()` отдаёт C-строку).

Строковые модификаторы приводят числа и bool к тексту по правилам вывода;
длины считаются в символах UTF-8, битый байт — один символ. Числовые
принимают только числа. Неподходящий тип — null, а не ошибка.

Реализация — `viewmodifier.c`: статический реестр `viewmodifier_t`
(`apply` для обычных, `output` для `nl2br`), строки результатов — в
`arena_t`, которую рендер сбрасывает после каждого тега. Модификаторы не
создают контейнеров: `first`/`last` возвращают токен документа, поэтому
коллекция `for` всегда принадлежит документу.

## Ошибки

* **Ошибка синтаксиса** (незакрытый тег, `{{ a + }}`, `{% unknown %}`,
  незакрытая строка, неизвестный модификатор, неверное число аргументов,
  `raw`/`nl2br` не в корне `{{ }}`) — весь `render` возвращает `NULL`,
  причина пишется в лог (`log_error`).
* **Ошибка данных** (нет переменной, индекс за границей, деление на ноль,
  несовместимые типы) — выражение даёт null: пустой вывод, ложное условие,
  пропущенный цикл.

## Низкоуровневый API

Обычно не нужен — `render` делает всё сам. Для инструментов и тестов:

```c
// разбор шаблона в дерево тегов
viewparser_t* parser = viewparser_init("views", "/index.html");
if (viewparser_run(parser)) {
    view_tag_t* root = viewparser_move_root_tag(parser); // забрать владение
    // ...
    root->free(root);
}
viewparser_free(parser);

// разбор и вычисление одного выражения; viewexpr_parse_output() — для
// тега {{ }}, где в корне допустимы raw и nl2br
viewexpr_node_t* expr = viewexpr_parse("a.b[0] | upper", 14);
arena_t arena;
arena_init(&arena);
viewexpr_scope_t scope = { my_resolve, my_data, &arena }; // NULL вместо арены: модификаторы, создающие строки, дают null
viewexpr_value_t value = viewexpr_eval(expr, &scope);
// value заимствует строки у AST, документа и арены — использовать до освобождения
arena_free(&arena);
viewexpr_node_free(expr);
```

`viewexpr_scope_t.resolve` получает первое имя пути (`a` в `a.b[0]`) и
возвращает `viewexpr_value_t`; остальную часть пути вычислитель проходит
сам по JSON-токенам. Рендер использует это для переменных циклов: сначала
ключ/элемент объемлющих `for`, затем поля корня документа.

## Кэширование

Первый `render` пути кладёт разобранное дерево в `viewstore` (потокобезопасно,
под блокировкой). Повторные рендеры того же пути файл не перечитывают.
Изменили шаблон на диске — перезапустите сервер.
